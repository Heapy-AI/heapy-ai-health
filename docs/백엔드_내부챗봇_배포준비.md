# 백엔드 내부 챗봇 배포 준비

- 작성자: 김진우
- 상태: 연결 준비 코드. 실제 배포·앱 연동 완료 아님.

## 진입점 구분

기존 단독 웹 데모는 `app.main:app`을 유지한다. 공용 모델 초기화만 `app.core.runtime`으로 이동했다. EC2용 Docker 진입점은 `app.internal:app`이며 데모 로그인·직접 개인 DB 쓰기 라우터를 등록하지 않는다. 업무 대화 저장과 소유권은 Spring Boot가 담당한다.

첫 연결 준비 API는 `POST /internal/chat/answer`다. 공개 앱 API가 아니며 외부 노출하지 않는다. `Authorization: Bearer <내부 서비스 인증값>`이 필요하고, 설정이 없거나 32자 미만이면 기동을 거절한다. 사용자 토큰을 내부 서비스 인증값으로 사용하지 않는다.

## 요청 제한

| 필드 | 제한 |
| --- | --- |
| contractVersion | 필수, `1.0` |
| message | 필수, 공백만 입력 불가, 1~2,000자 |
| history | 최대 20개, 기본 빈 목록 |
| history.role | user 또는 assistant |
| history.content | 1~8,000자 |
| summary | 최대 4,000자, 기본 빈 문자열 |
| persona | coach 또는 professional, 기본 coach |
| personalContext | Spring이 소유권을 검증한 문맥, 최대 20,000자 |

전체 본문은 262,144바이트 이하이며 추가 필드를 거절한다. 검증 오류 응답에는 원래 입력값을 포함하지 않는다. 개인 식별자나 DB 로그인 키를 요청으로 받지 않는다.

응답은 answer, citations, summary, metadata다. 인용은 검증된 결과가 실제 참조한 문서의 제목·문서 ID·HTTPS 링크만 최대 12개 반환한다. 전체 검색 청크나 공급자 오류는 반환하지 않는다. 기관 기록으로부터 새로운 진단명을 저장하는 기능은 없다.

오류는 401 내부 인증 실패, 413 전체 바이트 초과, 422 형식 오류, 503 준비 중 또는 생성 실패다. 응답은 저장 캐시를 금지한다. `GET /health/ready`는 모델 초기화와 챗봇 객체 준비가 완료돼야 200을 반환한다.

## 남은 연결

`POST /internal/chat/stream`은 같은 인증·요청 제한을 적용하며 status, delta, done, error 이벤트를 반환한다. done에는 최종 검증된 answer, citations, summary, metadata가 있다. 오류 이벤트에 공급자 예외를 포함하지 않는다. Spring은 최종 답변과 생성 도중의 부분 답변을 구분해 저장한다. 내부 토큰을 공개 앱에 그대로 전달하지 않고 최종 검증 후 답변을 표시한다.

Spring의 공개 SSE·멱등성·저장과 프런트 챗봇 탭 연결은 별도 프로젝트의 로컬 구현 단계다. 실제 공유 DB 추가 구조·배포·앱 연결 검증 전에는 준비 완료로 판정하지 않는다.

## CI/CD와 비밀 설정

`.github/workflows/fastapi.yml`은 검증 후 dev 배포를 수행한다. 저장소 변수 DEPLOY_ENABLED가 true여야 배포 작업이 열린다. OIDC 역할·ECR·고정 SSM 문서는 `scripts/deploy/render_infrastructure.py`로 검토용 CloudFormation JSON을 생성한다. 이 도구는 AWS를 실행하지 않는다.

실행 비밀 설정은 EC2 `/opt/heapy/fastapi.env`에 안전하게 준비해야 하며 아직 준비 완료로 확인되지 않았다. GOOGLE_API_KEY 또는 GEMINI_API_KEY, PINECONE_API_KEY 및 내부 서비스 인증이 필요하다. 의료용어 조회 설정은 실제 권한과 저장소 계약을 별도로 검증한다. 이미지·Git·Actions·SSM 명령 본문에 비밀값을 넣지 않는다.
