# 내부 건강 분석 API

- 작성자: 김진우
- 기준: 2026-09-10 사용자 건강탭 구현·적용 승인

## 배포 범위

기존 `app.internal:app`에 `POST /internal/health/analyses`를 등록한다. 기존 챗봇 경로와 데모의 `app.main` 실행 방식은 유지한다. 이 변경만으로 모바일 건강탭, 데모 웹 화면, 자정 예약 실행이 활성화되지는 않는다.

## 호출 계약

Spring 서버만 기존 내부 Bearer 토큰으로 호출한다. 최대 요청 크기는 기존 내부 서버 제한인 262,144바이트다. `contractVersion`은 `1.0`, `category`는 `bio`, `activity`, `nutrition`, `sleep`, `checkup`, `overall` 중 하나다.

`analysisDate`는 한국 날짜이고 `cutoff`는 그 날짜의 한국 자정에 해당하는 시간대가 포함된 시각이다. `records`는 영역별 레코드 배열이고 전체 10,000행을 넘길 수 없다. `checkups`는 최대 100회다. 사용자 식별자나 데이터베이스 인증 정보를 받지 않는다.

생활 데이터의 열 이름은 현재 업무 DB 기준이다. 활동 거리는 `distance_m`의 미터를 킬로미터로, 수면은 분을 시간으로 바꿔 연구 서비스에 전달한다. 기록 날짜는 한국 날짜로 정규화한다. 자정 이후 측정값과 종료하지 않은 수면은 제외한다.

검진 입력은 회차마다 `date`, `results`를 갖고 항목은 `item_code`, `item_name`, `value`, `unit`, `status`를 전달한다. 기관 판정은 전달받은 값을 사용한다.

자료 부족은 `data_insufficient`, 생성 성공은 `generated`와 `report`를 반환한다. 인증·입력 오류는 각각 401·422이며 생성 오류는 입력 원문을 포함하지 않는 503으로 응답한다. 별도 데이터베이스 읽기·쓰기나 분석 내용 영구 저장은 하지 않는다.

## 실행 책임

사용자별 하루 1회 실행권, 자정 스케줄, 당일 결과 임시 보관은 Spring 담당이다. 이 API 자체는 예약 작업이나 사용자별 실행 이력을 관리하지 않는다. 내부 호출에서 연구 서비스 모델의 자동 재시도는 0회로 설정한다. 데모의 기본 재시도 설정은 바꾸지 않는다.

## 검증과 적용 제한

합성 데이터·모의 응답으로 내부 인증, 날짜·단위 정규화, 숨은 재호출 방지와 오류 비노출을 검증한다. 실제 모델의 분석 품질과 모든 그래프의 계산 일치, 기존 챗봇과의 부하는 별도 통합 검증 대상이다. 앱과 자정 작업은 이 경로가 등록되었다는 이유만으로 활성화하지 않는다.
