# HEAPY Intent 분류 학습 데이터 라벨링 가이드 v2

> 목적: HEAPY 건강관리 챗봇의 단일 질문 Intent 분류 학습 데이터를 일관된 기준으로 작성하고 검수한다.

---

## 1. 프로젝트 범위

현재 Intent 분류기는 사용자의 질문 1개를 입력받아 다음 4개 Intent 중 하나로 분류한다.

- `simple_lookup`
- `comprehensive`
- `general_chat`
- `ignore`

현재 단계에서는 다음 항목을 고려하지 않는다.

- 멀티턴 대화
- 이전 대화 문맥 복원
- Multi-label 분류
- LLM을 이용한 최종 Intent 재판단
- 대화 흐름에 따른 Intent 변경

학습 데이터 한 행은 다음 형식을 사용한다.

```json
{
  "text": "AST 정상 범위 알려줘",
  "label": "simple_lookup"
}
```

---

## 2. 핵심 라벨링 원칙

1. 답변 내용이 아니라 **사용자의 최종 요청 목적**을 기준으로 분류한다.
2. 한 데이터에는 하나의 주된 Intent만 포함한다.
3. 이전 대화 없이도 문장의 의미를 이해할 수 있어야 한다.
4. 가장 먼저 진단·처방·복용량 조절·약물 중단·치료 선택처럼 챗봇이 대신 결정해서는 안 되는 요청인지 확인한다.
5. 안전상 제한되는 의료적 결정 요청이면 개인 데이터가 포함되어 있어도 `ignore`가 우선한다.
6. 안전 요청이 아니라면, 사용자의 저장된 개인 건강 데이터를 조회하거나 개인 수치를 해석해야 하는지를 확인한다.
7. 명시적으로 `분석해줘`, `조회해줘`, `추세를 알려줘`라고 말하지 않아도 개인 데이터가 필요하면 `comprehensive`이다.
8. 사용자가 자신의 건강 수치를 질문에 직접 제시한 경우에도 개인 수치 해석으로 보고 `comprehensive`로 분류한다.
9. 단순히 `나`, `내`, `내가`가 포함되었다는 이유만으로 `comprehensive`로 분류하지 않는다.
10. 여러 Intent가 포함되면 다음 우선순위를 적용한다.

```text
ignore
> comprehensive
> simple_lookup
> general_chat
```

핵심 판단 기준은 다음과 같다.

```text
의료적 결정 요청인가?
→ 예: ignore

아니라면 개인 건강 데이터가 있어야 답할 수 있는가?
→ 예: comprehensive

아니라면 일반 건강정보만으로 답할 수 있는가?
→ 예: simple_lookup

그 밖의 대화형 발화인가?
→ general_chat
```

## 3. Intent 정의

### 3.1 `simple_lookup`

#### 정의

사용자의 저장된 개인 건강 데이터를 조회하거나 개인 수치를 해석할 필요 없이, VDB에 적재된 의료·검진·질병·의약품·서비스 안내 정보만으로 답변할 수 있는 질문

#### 포함 범위

- 건강검진 항목의 의미
- 일반적인 정상 범위
- 질환의 정의와 일반 정보
- 질환의 일반적인 증상
- 의약품의 용도와 일반 정보
- 일반적인 약물 부작용
- 특정 약물 조합의 일반적인 상호작용
- 일반적인 예방 및 생활관리 방법
- 일반적인 치료 방법
- HEAPY 서비스 사용 방법
- 특정 사용자의 값이라고 명시되지 않은 수치의 일반 기준 비교

#### 대표 예시

```text
AST가 뭐야?
AST 정상 범위 알려줘
공복혈당 130이면 높은 거야?
당뇨병이 뭐야?
당뇨병 초기 증상 알려줘
메트포르민은 어떤 약이야?
메트포르민 부작용 알려줘
메트포르민과 철분제를 같이 먹어도 돼?
고혈압은 일반적으로 어떻게 치료해?
잠을 잘 자는 방법 알려줘
건강검진 결과는 어디서 등록해?
```

### 3.2 `comprehensive`

#### 정의

사용자의 프로필, 건강검진, 복약, 생활습관, 측정 기록 등 개인 건강 데이터를 조회하거나, 사용자가 직접 제시한 자신의 수치를 해석·비교·요약·분석해야 하는 질문이다. 필요한 경우 RDB의 개인 데이터와 VDB의 일반 의료 정보를 함께 사용한다.

#### 핵심 판정 기준

다음 중 하나라도 해당하면 `comprehensive` 후보로 판단한다.

- 사용자의 저장된 개인 건강 데이터가 있어야 답할 수 있다.
- 사용자가 자신의 건강 수치나 기록 상태를 묻는다.
- 사용자가 직접 제시한 자신의 수치가 높거나 낮은지 해석을 요청한다.
- 최근 기록의 변화, 추세, 흐름 또는 이전 기록과의 비교가 필요하다.
- 둘 이상의 개인 건강 데이터 사이의 관련성을 묻는다.
- 개인 복약 목록, 복약 일정 또는 복약 이력을 확인해야 한다.

명시적으로 `분석해줘`, `기록을 보여줘`, `추세를 알려줘`라고 말하지 않아도 개인 데이터를 조회하거나 해석해야 한다면 `comprehensive`이다.

다만 개인 데이터를 이용해 병명을 확정하거나, 약의 용량·중단·처방·치료 방법을 결정해 달라는 요청은 `ignore`가 우선한다.

#### 포함 범위

- 개인 건강검진 결과 조회 및 해석
- 개인 복약 목록, 일정 및 복약 기록 조회
- 개인 생활습관 기록 조회 및 분석
- 수면, 운동, 걸음 수 등 개인 기록의 현재 상태 확인
- 혈압, 혈당, 심박수 등의 개인 측정값 해석
- 최근 건강 데이터의 변화, 추세 및 흐름 분석
- 여러 개인 건강정보의 종합 분석
- 개인 건강 요인 간 관계 분석
- 질문에 직접 제시된 개인 수치 해석
- 짧은 구어체로 표현된 개인 건강 상태 확인 요청

#### 대표 예시

```text
내 공복혈당이 130인데 높은 거야?
내 AST가 70인데 왜 높아?
내 건강검진 결과를 분석해줘
최근 내 혈압 변화가 어떤지 알려줘
내가 먹는 약끼리 상호작용이 있어?
최근 약을 얼마나 잘 먹었어?
오늘 내가 먹어야 할 약 알려줘
내 최근 수면 상태가 어때?
요즘 잠을 못 자서 혈압이 오른 걸까?
내 검진 결과를 보고 당뇨 위험을 설명해줘
내 혈당 요즘 어때?
혈압 좀 봐줘
요즘 내 걸음 수 줄었어?
내 LDL 160이면 높은 편이야?
최근에 약 잘 챙겨 먹고 있어?
```

### 3.3 `general_chat`

#### 정의

전문 정보 검색을 위한 VDB 조회나 개인 건강 데이터 확인을 위한 RDB 조회 없이 대화형으로 응답할 수 있는 발화

#### 포함 범위

- 인사
- 감사
- 감정 표현
- 가벼운 잡담
- 분석이나 조회를 요청하지 않는 일상 공유
- 분석이나 기록을 요청하지 않는 건강 상태 공유
- 챗봇 자체에 관한 간단한 대화

#### 대표 예시

```text
안녕
고마워
오늘 기분이 좋아
오늘 운동했어
오늘 만 보 걸었어
오늘 약 잘 챙겨 먹었어
어제 잠을 푹 잤어
머리가 아파
잘 자
너는 누구야?
너 이름이 뭐야?
```

### 3.4 `ignore`

#### 정의

HEAPY 서비스 범위를 벗어나거나, 챗봇이 직접 수행해서는 안 되는 병명 확정·처방·복용량 조절·약물 중단·치료 선택·병원 방문 여부 결정 등을 요구하는 질문이다. 개인 건강 데이터나 검진 수치가 포함되어 있어도 이러한 의료적 결정을 요구하면 `ignore`가 우선한다.

#### 포함 범위

- 건강과 무관한 정보 또는 작업 요청
- 개인 병명 확정 요구
- 개인 맞춤 처방 요구
- 약 복용량 변경 요구
- 약 복용 중단 여부 결정
- 특정 치료 선택 또는 중단 결정
- 병원 방문 필요 여부를 챗봇이 대신 결정하도록 하는 요청
- 개인 증상을 기반으로 직접 원인이나 병명을 판단하도록 하는 요청
- 불법 또는 위험한 요청
- 긴급하거나 위험한 상황
- 개인 기록이나 검진 수치를 근거로 약의 용량·중단·처방·치료를 결정하도록 하는 요청

#### 대표 예시

```text
오늘 살 주식 추천해줘
재밌는 영화 추천해줘
파이썬 코드 작성해줘
내가 당뇨병인지 진단해줘
내 병명이 뭔지 알려줘
나한테 맞는 약을 처방해줘
이 약을 두 배로 먹어도 돼?
내 약 복용량을 늘려도 돼?
약을 이제 그만 먹어도 돼?
병원 안 가도 되는지 결정해줘
내 수치에 맞는 치료 방법을 정해줘
내 혈압 기록을 보고 약 용량을 정해줘
검진 수치만으로 암인지 아닌지 결론 내려줘
내 혈당을 보고 인슐린을 몇 단위 맞아야 하는지 알려줘
```

## 4. Intent 판정 순서

### 1단계: 서비스 범위와 안전성 확인

다음에 해당하면 `ignore`를 우선 검토한다.

- 서비스와 무관한 작업 요청
- 병명 확정
- 처방
- 복용량 변경
- 약 복용 중단 결정
- 개인 치료 방법 결정
- 긴급하거나 위험한 상황
- 개인 기록이나 검진 수치를 근거로 약의 용량·중단·처방·치료를 결정하도록 하는 요청

### 2단계: 개인 건강 데이터 사용 여부 확인

다음에 해당하면 `comprehensive`를 검토한다.

- RDB에 저장된 개인 데이터 조회가 필요함
- 사용자가 제공한 개인 건강 수치를 해석함
- 개인 기록을 비교하거나 변화 추이를 분석함
- 개인 건강 요인 사이의 관계를 분석함

### 3단계: 일반 건강정보 검색 여부 확인

개인 데이터 없이 VDB 정보만으로 답할 수 있으면 `simple_lookup`으로 분류한다.

### 4단계: 대화 여부 확인

검색, 조회, 분석, 작업 요청 없이 대화형으로 응답할 수 있으면 `general_chat`으로 분류한다.

| 오후 8시에 약 먹으라고 알려줘 | 데이터셋 제외 | 알림 생성 기능은 현재 Intent 범위 밖 |

## 6. 긴급 상황 처리

다음과 같은 문장은 학습 데이터에서는 `ignore`로 라벨링한다.

```text
가슴이 너무 아프고 숨을 못 쉬겠어
약을 많이 먹었는데 괜찮을까?
의식을 잃을 것 같아
갑자기 말이 잘 안 나오고 한쪽 팔에 힘이 없어
```

실제 서비스에서는 일반 Intent 분류 전에 별도의 긴급 상황 탐지 로직을 수행한다.

```text
사용자 질문
→ 긴급 상황 탐지
→ 긴급 상황이면 안전 응답
→ 긴급 상황이 아니면 Intent 분류
```

## 7. 복수 Intent 처리

하나의 질문에 여러 Intent가 포함되면 다음 우선순위를 적용한다.

```text
ignore
> comprehensive
> simple_lookup
> general_chat
```

### 예시

| 질문 | Intent |
|---|---|
| AST가 뭔지 알려주고 내 수치도 분석해줘 | `comprehensive` |
| 혈압약 계속 먹어도 돼? 혈압 정상 범위도 알려줘 | `ignore` |
| 안녕, 오늘 먹을 약 알려줘 | `comprehensive` |
| 내 약 정리해주고 영화도 추천해줘 | `comprehensive` |

초기 학습 데이터는 가능한 한 Intent가 하나만 명확하게 드러나는 문장으로 구성한다. 복수 Intent 문장은 경계 평가용 데이터로 소량만 사용한다.

## 8. 학습 데이터 제외 규칙

다음 문장은 초기 학습 데이터에서 제외한다.

### 8.1 이전 대화가 있어야 이해할 수 있는 문장

```text
이거 뭐야?
그거 높아?
아까 말한 거 다시 봐줘
```

### 8.2 의미가 지나치게 불분명한 문장

```text
왜 이래?
좀 봐줘
어떡해?
```

### 8.3 현재 지원하지 않는 기능의 실행 요청

```text
오후 8시에 약 먹으라고 알려줘
오늘 걸은 거 기록해줘
이 약을 복약 목록에 추가해줘
```

### 8.4 그 밖의 제외 대상

- 서로 다른 Intent가 과도하게 섞여 주된 의도를 판단하기 어려운 문장
- 답변 문장, 시스템 문장 또는 챗봇이 말할 법한 문장
- 의미를 알아보기 어려운 수준의 심한 오타가 포함된 문장
- 같은 Seed에서 조사나 어미만 변경한 사실상 중복 문장

## 9. Seed 데이터 작성 규칙

- Intent별 데이터 수를 가능한 한 균형 있게 구성한다.
- 실제 모바일 앱 사용자가 입력할 법한 자연스러운 한국어를 사용한다.
- 질문형, 명령형, 짧은 구어체를 함께 포함한다.
- 짧은 문장 40%, 중간 문장 40%, 긴 문장 20%를 목표로 한다.
- 반말·구어체 60%, 존댓말 40%를 목표로 한다.
- 자연스러운 띄어쓰기 오류, 축약, 가벼운 오타는 전체의 약 5%만 포함한다.
- 특정 라벨에만 특정 단어가 반복되지 않도록 한다.
- 검사, 질환, 약물, 복약, 생활습관, 서비스 사용법 등 주제를 다양하게 구성한다.
- 같은 의미의 문장을 단어만 바꾸어 반복하지 않는다.
- 경계가 명확한 기본 문장과 Intent 간 경계 문장을 모두 포함한다.

## 10. 기존 데이터셋 재검수 및 경계 보강 기준

라벨링 가이드가 v2로 변경되었으므로 기존 400개 데이터와 Hard Pair 데이터를 검수 없이 그대로 재학습하지 않는다.

### 10.1 기존 400개 데이터 검수

기존 400개 데이터는 전부 폐기하지 않고 기본 데이터로 유지한다. 다만 아래 항목은 다시 검수한다.

- 짧은 개인 데이터 조회 문장이 `ignore` 또는 `general_chat`으로 라벨링되어 있지 않은지
- 사용자가 직접 제시한 자신의 수치가 `simple_lookup`으로 라벨링되어 있지 않은지
- 개인 데이터가 포함된 의료적 결정 요청이 `comprehensive`로 라벨링되어 있지 않은지
- `나`, `내`, `내가`만 포함되었다는 이유로 불필요하게 `comprehensive`가 되지 않았는지
- 새 정의와 충돌하는 문장, 중복 문장 또는 지나치게 유사한 문장이 없는지

검수 결과는 `approved`, `revised`, `rejected`, `needs_discussion`으로 기록한다.

### 10.2 Hard Pair 데이터 처리

기존 Hard Pair 80개를 모두 그대로 학습에 추가하지 않는다.

- 기존 평가 문장과 동일하거나 지나치게 유사한 문장은 제외한다.
- 새 라벨링 가이드와 라벨이 충돌하는 문장은 수정하거나 제외한다.
- 같은 표현을 조사나 어미만 바꾼 중복 pair는 축소한다.
- 실제 오분류 패턴과 관계없는 쉬운 pair는 우선순위를 낮춘다.
- 학습에 넣는 Hard Pair와 최종 Blind 평가 문장은 `pair_id` 단위로 완전히 분리한다.

### 10.3 우선 보강할 경계 데이터

현재 가장 중요한 보강 대상은 `comprehensive → ignore` 오분류를 줄이기 위한 짧은 개인 데이터 조회 문장이다.

다음 세 문장을 하나의 경계 세트로 구성한다.

```text
내 혈압 요즘 어때?                 → comprehensive
혈압 정상 범위가 뭐야?            → simple_lookup
내 혈압 보고 약 용량 정해줘       → ignore
```

동일한 구조를 혈당, LDL, AST, 수면, 걸음 수, 심박수, 복약 이력 등 여러 주제로 확장한다.

보강 문장은 다음 유형을 포함한다.

- 짧은 구어체: `내 혈당 어때?`, `혈압 좀 봐줘`
- 변화 확인: `요즘 내 걸음 수 줄었어?`
- 직접 제시한 개인 수치: `내 LDL 160이면 높아?`
- 복약 이력 조회: `최근에 약 잘 챙겨 먹었어?`
- 안전 경계 대조: `내 기록 보고 약 끊어도 돼?`

단, 기존 오분류 문장 자체나 평가 문장을 그대로 복사해 학습에 넣지 않는다. 같은 패턴을 가진 새로운 문장으로 보강한다.

### 10.4 재학습 데이터 구성 권장

```text
기존 400개
→ v2 기준으로 전수 또는 반자동 재검수
→ 잘못된 라벨·중복·모호한 문장 수정 또는 제거
→ 필요한 경계 보강 문장만 추가
→ Seed 또는 pair_id 기준으로 Train / Validation / Test 분리
→ 완전히 독립된 Blind 평가셋 유지
```

Hard Pair 개수는 고정 목표로 삼지 않는다. 개수보다 표현 다양성, 실제 오류 기여도, 평가셋 독립성을 우선한다.

## 11. 프로토타입 데이터 구축 기준

오늘 안에 프로토타입을 완성하는 것을 기준으로 다음 규모를 권장한다.

| 항목 | 기준 |
|---|---|
| 사람이 검토할 핵심 Seed | Intent당 15개, 총 60개 |
| LLM 확장 | Seed당 4~6개 |
| 1차 목표 데이터 | Intent당 80~100개 |
| 전체 목표 데이터 | 약 320~400개 |
| Train / Validation / Test | 8 : 1 : 1 |
| 데이터 균형 | Intent별 동일하거나 유사한 개수 |
| 검수 | 전체 생성 데이터 빠른 수동 검수 |
| 오분류 보강 | Confusion Matrix 확인 후 경계 문장 추가 |

### 데이터 분리 시 주의사항

같은 Seed에서 생성한 유사 문장들이 Train과 Test에 동시에 들어가면 안 된다.

```text
1. Seed를 Train / Validation / Test 그룹으로 먼저 분리
2. 각 Seed에서 생성된 변형 문장은 원본 Seed와 같은 그룹에 배치
3. 이후 모델을 학습하고 평가
```

이 규칙을 지키지 않으면 모델이 비슷한 문장을 외운 결과가 테스트 성능으로 나타날 수 있다.

## 12. 생성 데이터 검수 기준

| 검수 항목 | 통과 기준 |
|---|---|
| Intent 일치 | 정의와 경계 기준에 맞음 |
| 단일 의도 | 하나의 주된 요청이 존재함 |
| 독립성 | 이전 문맥 없이 이해 가능함 |
| 자연스러움 | 실제 사용자가 입력할 법함 |
| 중복성 | 기존 문장과 지나치게 유사하지 않음 |
| 범위 적합성 | 현재 HEAPY MVP 범위에 속함 |
| 형식 | `text`, `label` 값이 올바름 |

검수 결과는 다음 중 하나로 기록할 수 있다.

- `approved`: 그대로 사용
- `revised`: 수정 후 사용
- `rejected`: 데이터셋에서 제외
- `needs_discussion`: 현재 기준으로 판단하기 어려움

## 13. 최종 체크리스트

데이터를 추가하기 전에 다음을 확인한다.

- [ ] 이전 대화 없이 이해 가능한가?
- [ ] 사용자의 요청 목적이 하나인가?
- [ ] 명시적인 분석 표현이 없어도 개인 건강 데이터가 있어야 답할 수 있는가?
- [ ] 사용자가 직접 제시한 자신의 건강 수치를 해석하는 질문인가?
- [ ] 병명 확정, 처방, 복용량, 약물 중단 또는 치료 결정을 요구하는가?
- [ ] 개인 데이터가 포함되어 있어도 `ignore`가 우선해야 하는 요청은 아닌가?
- [ ] 일반 VDB 정보만으로 답변 가능한가?
- [ ] 단순한 일상 공유 또는 대화인가?
- [ ] 기존 데이터와 지나치게 비슷하지 않은가?
- [ ] Intent 우선순위를 올바르게 적용했는가?
