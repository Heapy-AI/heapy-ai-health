# 평가용 데이터

## `lifestyle_cases.jsonl` — 생활건강 프롬프트 평가 구간

프롬프트 v1~v4를 견주는 데 쓰는 **합성 구간 8개**와 그 정답지다.
한 줄에 한 구간씩 들어 있다.

```
구간 8개 · 기록 594건
```

| 구간 | 기록 | 벗어남 | 겨누는 물음 |
|---|---|---|---|
| 영양-전부정상 | 60 | 0개 | 없는 문제를 지어내는가 |
| 영양-여럿벗어남 | 60 | 7개 | 많을 때 빠뜨리는가 |
| 생체-하나만벗어남 | 150 | 1개 | 하나뿐일 때는 짚는가 |
| **생체-혈압상승** | 130 | 2개 | **오르는 흐름을 짚는가** (전체 뚜렷하게 · 최근 조금씩) |
| 생체-기록드묾 | 15 | 3개 | 근거가 얇은데 단정하는가 (전부 신뢰도 부족) |
| 수면-구성문제 | 30 | 2개 | 잠의 길이와 구성을 가리는가 |
| **활동-들쭉날쭉** | 69 | 1개 | **평균보다 꾸준함을 먼저 말하는가** (걸음·활동칼로리 편차 큼, 튄 날 1일) |
| 활동-운동드묾 | 69 | 0개 | 길이와 빈도를 가리는가 |

### 값이 날마다 흔들린다

처음 만든 구간은 날마다 값이 똑같았다(나트륨 3,600이 30일 내내). 그러면 서비스가
내는 여섯 신호 가운데 **수준·빈도 둘만 살아 있고** 방향은 전부 '큰 변화 없음',
안정성은 전부 '안정적'이 된다. 그 상태로는 "조금씩 오르는 흐름"을 프롬프트가
제대로 옮기는지 잴 수 없다.

지금은 구간마다 흔들림 폭(`spread`)과 추세(`drift`), 튀는 날(`spike`)을 정해 넣는다.
흔들림은 씨앗을 고정한 난수라 언제 돌려도 같은 값이 나온다. 다만 **조용해야 하는
구간**(영양-전부정상)만은 물결로 흔든다 — 난수는 서른 번쯤 뽑으면 표본 표준편차가
작게 잡히는 날이 있어 '평소와 크게 다른 날'로 걸리고, 그 한 날이 거짓양성 지표를
흐리기 때문이다.

### 한 줄의 모양

```json
{
  "case": "영양-여럿벗어남",
  "domain": "nutrition",
  "intent": "벗어난 항목이 여럿이다. 넉 줄 안에 몇 개나 담는지 본다.",
  "expected": {
    "snapshot_at": "2026-09-10",
    "off_range": [{"metric": "나트륨", "level": "기준을 크게 벗어남", "frequency": "거의 매번"}],
    "moving": [{"metric": "나트륨", "full": "조금씩 높아지는 흐름", "recent": "조금씩 높아지는 흐름"}],
    "unstable": [],
    "low_confidence": [],
    "anomalies": ["나트륨", "지방 비중"],
    "separately_measured": ["meal_pattern"]
  },
  "window": { "food": {"rows": [...]}, "water": {"rows": [...]} }
}
```

### 이 파일은 정답지가 아니라 스냅샷이다

**채점은 이 파일을 읽지 않는다.** 평가 하네스는 `window`를 서비스 코드에 넣어
그때그때 판정을 다시 계산한다. `expected`는 사람이 들여다보라고 함께 떠 둔 것이다.

그래서 **참고범위를 고치면 이 파일은 낡는다.** 실제로 2025 한국인 영양소 섭취기준으로
갈아 끼우면서 여러 항목의 판정이 달라졌다. 기준을 손댔다면 다시 떠야 한다.

```bash
python evaluation/lifestyle_eval_cases.py --export
```

### 왜 기록을 만들어 냈나

정답지를 사람이 라벨링하지 않고 코드가 계산하므로, 입력이 실제 기록이냐 만들어 낸
기록이냐가 정답지의 신뢰도를 흔들지 않는다. 대신 **의도한 상황을 골라 만들 수 있다.**
실제 사용자 다섯 명의 기록으로는 '전부 정상인 달'이나 '기록이 드문 달'을 구할 수 없다.

다만 합성만으로는 실제 사용자에서의 성능을 증명하지 못한다. 평가 하네스는 이 구간과
**실제 기록을 함께** 돌린다. 합성은 어디서 무너지는지 찾는 쪽, 실데이터는 현실에서도
그런지 보는 쪽이다.

### 만드는 곳

`evaluation/lifestyle_eval_cases.py` — 구간은 파라미터로 적혀 있다.
`sodium=3600, dietary_fiber=15`처럼 읽히므로 무엇을 겨눈 케이스인지 표보다 잘 보인다.
